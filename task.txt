بخش ۲: بک‌اند

BE-1. شکستن God Classes (بالاترین اولویت بک‌اند)


 Controllers/WarehouseController.cs (۲۸۵۳ خط) → تجزیه به:

WarehouseInventoryController (موجودی)
WaybillController (اگه از قبل نیست، ادغام یا جدا)
WarehouseReportsController
منطق کسب‌وکار مشترک بره تو Modules/Inventory/Application/*Service.cs



 Controllers/FinancialController.cs (۱۸۹۷ خط، ۱۴ dependency) → تجزیه به InvoiceController, LedgerController, TaxReportController + application services جدا برای هر domain.
 Services/WorkflowService.cs (۱۸۷۶ خط) → جدا کردن به:

WorkflowRoutingService
WorkflowAttachmentService
WorkflowDecisionService
WorkflowSlaService
همه با اینترفیس مشخص و DI واقعی (حذف new DecisionEngine() و امثالش).



 هدف عددی: هیچ کنترلر/سرویسی بیشتر از ~۴۰۰-۵۰۰ خط نباشه.


BE-2. یکسان‌سازی معماری Modules/ در برابر Controllers/Services قدیمی


 یه سند کوتاه (docs/architecture-migration.md) بساز که مشخص کنه کدوم domain ها (Finance, Workflow, Inventory, Platform, Identity, Office) کامل به Modules/ مهاجرت کردن و کدوم نه.
 برای هر domain که duplication منطق داره (مثل Finance که هم Controllers/FinancialController و هم Modules/Finance/Application/FinanceLedgerService منطق مشابه دارن)، یکی رو source of truth کن و اون یکی رو یا حذف کن یا صرفاً wrapper کن.


BE-3. رفع Duplicate DI Registrations


 Program.cs رو کامل مرور کن و سرویس‌های دوبار-register-شده (tenant، workflow، outbox، notification) رو یکی کن.
 یه تست بنویس که با reflection روی IServiceCollection قبل از Build() چک کنه هیچ سرویس کلیدی بیشتر از یه بار register نشده.


BE-4. تقویت TenantMigrationHostedService


 به‌جای _ = Task.Run(...) خام، نتیجه‌ی Task رو نگه دار و در StopAsync منتظر تکمیل/cancel صحیح بمون.
 یه health-check endpoint (/health/tenant-migrations) اضافه کن که وضعیت per-tenant (pending/running/failed/completed) رو نشون بده.


BE-5. Swagger / OpenAPI برای API عمومی — قابلیت جدید


 Swashbuckle.AspNetCore اضافه کن، روی همه‌ی endpointهای API (AuthApi, WorkInboxApi, و هر کدوم دیگه) annotation بذار.
 یه صفحه‌ی مستندسازی (/api-docs یا /swagger) که فقط برای نقش ادمین/دولوپر در دسترسه (پشت authorization، نه public).


BE-6. Rate Limiting


 از Microsoft.AspNetCore.RateLimiting (built-in .NET) استفاده کن:

Login endpoint: محدودیت سخت‌گیرانه (مثلاً ۵ تلاش در دقیقه به ازای IP) برای جلوگیری از brute-force.
AI Assistant / ManagementDashboard AI endpoints: محدودیت per-user (مثلاً ۲۰ درخواست در ساعت) چون هزینه‌ی API داره.
سایر endpointهای عمومی: یه محدودیت پایه‌ی معقول.





BE-7. اجباری‌کردن 2FA برای نقش‌های حساس


 بررسی کن RequiresTwoFactor تو Login.cshtml.cs فعلاً enforced هست یا فقط زیرساخت خالیه.
 یه پالیسی اضافه کن: کاربرهایی با نقش SecurityAdmin, FinanceManager, یا هر نقش حساس دیگه، اگه 2FA فعال نکرده باشن، بعد از لاگین به یه صفحه‌ی "فعال‌سازی اجباری 2FA" هدایت بشن.


BE-8. Real-time Notifications با SignalR — قابلیت جدید


 یه NotificationHub : Hub اضافه کن.
 NotificationService موجود رو طوری تغییر بده که علاوه بر ذخیره تو دیتابیس، از طریق SignalR به کلاینت‌های متصل push کنه (بج اعلان بدون نیاز به رفرش صفحه).
 اول روی WorkInbox (کارهای جدید) و Notifications پیاده‌سازی کن، بعد بقیه.


BE-9. Webhook / Integration Events — قابلیت جدید (اگه هدف یکپارچه‌سازیه)


 یه جدول WebhookSubscriptions (URL، رویداد، tenant، secret برای HMAC signing) اضافه کن.
 رویدادهای کلیدی (فاکتور approve شد، workflow تمام شد) رو از طریق outbox pattern موجود (که ظاهراً از قبل هست) به این webhookها هم publish کن.


BE-10. افزایش پوشش تست


 تست‌های concurrency برای race condition fix شده‌ی WorkflowService (چند thread هم‌زمان درخواست SequenceNumber بدن، مطمئن شو duplicate نمی‌شه).
 تست integration برای authorization checks جدید (DownloadAttachment IDOR fix، IsSafeHost SSRF fix، AiSqlSafetyService.IsSafeQuery) — این‌ها حیاتی‌ترین بخش‌های امنیتی پروژه‌ان و نباید بدون تست regression بمونن.
 هدف: پوشش حداقل ۴۰٪ روی Services/ و Modules/*/Application/.


BE-11. Audit Log قابل Export


 بررسی کن AuditLogsController فعلاً امکان export به Excel/PDF داره یا نه؛ اگه نه، اضافه کن (با فیلتر بازه‌ی زمانی، کاربر، نوع عملیات) — برای حسابرسی خارجی enterprise لازمه.
